# Historical implementation record: 0.4.0

This records the implementation of the [improvement plan](improvement-plan.md) in four stages, completed during the October 5–6, 2026 preparation of version 0.4.0. It is a historical acceptance record, not a current test report or proof of publication. Test counts, development archive identities, and source-match statements apply to the recorded checkpoints. Current behavior is documented in the [reference](reference.md); publication is verified separately through the [release workflow](releasing.md).

| Stage | Scope | State |
| --- | --- | --- |
| 1. Routing correctness | Shared compatibility and model catalog; durable active-turn state; successful response/fallback evidence; request validation; stronger evaluation gates | Implemented; 394-test regression run passed before stage 2; installed-package checks passed |
| 2. Setup and diagnostics | Safe configuration merge/edit commands, effective-value provenance, strict active-provider validation, command help, local evaluator diagnostic | Implemented; 436-test regression run, syntax and installed-package checks passed |
| 3. Terminal polish and history | Shared bounded events, outcome records, optional metadata-only history, session commands, narrow status explanations, savings coverage | Implemented; 481-test stage regression passed; installed-package checks passed |
| 4. Measured performance and maintainability | Baselines, coalesced evaluation, bounded responses, asynchronous status persistence, release verification, contributor/docs checks | Implemented and verified: 551 tests, static checks and exact installed-archive checks passed; actual 16 GiB and 64 GiB evaluator measurements independently validated |

Stage 1 evidence: local mock tests cover all routing profiles, forced-tool incompatibility, malformed fields rejected before evaluation/upstream, retained active pins beyond expiry and under capacity pressure, parallel completion ordering, clean provider fallback ownership, failed and cancelled attempts, and new-task model downgrades. Gateway tests preserve response bytes and permission review data. The evaluator gates separately report transport, evaluator availability, rubric agreement, policy, profile-specific tier coverage, and task completion. New held-out multilingual, short-follow-up, and tier-influence cases were added before evaluator runs. Their mocked characterization checks validate the routing harness; no claim of measured real-model accuracy is made.

Every stage retains Jev as the default, native Ollama `/v1/systemone` support, automatic Sonnet/Opus switching in Auto mode, optional session logging disabled by default, and Claude-owned authentication and permission checks. Final completion requires the full regression suite, syntax checks, exact installed-package checks, performance evidence, and a requirement-by-requirement review of all four stages.

## Final local verification, October 5, 2026

- `npm test`: 551 tests passed, no failures, skips or cancellations.
- `npm run check`: 88 JavaScript files passed syntax checks; configuration/decision/event type contracts, producer-field checks and style policy passed.
- The final router candidate passed all 18 unchanged baseline-derived gates. Large-tool-catalog p95 was 3.037 ms against an 8.831 ms limit; concurrent identical evaluator calls fell from 480 to 60 per round. The recorded storage comparison also passed all four gates.
- After adding the returned hardware evidence, `npm run release:pack` created the local development archive with 50 verified public files. SHA-256: `3b6769aee673d7334214bb5ebddbc2cfb4b50f6cc2e96debe496e7a025b615dc`. Static checks and 17 release-verifier tests passed again after the package allowlist change; runtime source is unchanged from the full 551-test run.
- `node scripts/package-smoke.mjs --archive dist/claude-autorouter-0.3.7.tgz` installed and tested those exact bytes without rebuilding them. Configuration/help, all profiles, synthetic OAuth forwarding, local setup/diagnostics, history, stream cancellation, upstream SSE errors, partial-frame truncation, child failures, signals and cleanup passed. The independent upstream-failure cases preserve response bytes, display errors/incomplete completion, exclude failed usage from savings, and permit a same-prompt retry without falsely pinning the observed failed Opus model. A complete final delta followed by clean EOF retains its existing supported completion behavior.
- The finished release verifier checked the original public 0.3.7 workflow archive and isolated public install in one attempt, without publishing or modifying tags. The development archive above is different and must not be published as another 0.3.7.
- The larger-Mac transfer bundle has 37 allowlisted files and verified source hashes; its SHA-256 is `f3bbad523f6f54e497493b5725972fef81945e339f65b605331f8e794a09b4f7`. Its synthetic workload and rubric match the recorded 16 GiB measurement. No dependencies need installation.
